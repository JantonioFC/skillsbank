# Habilidades de Pruebas

Este documento lista las habilidades de la categoría "Testing" con una breve descripción de su función en español.

| Habilidad | Descripción |
| --- | --- |
| `ab-test-setup` | Guía estructurada para configurar pruebas A/B con puertas obligatorias para hipótesis, métricas y preparación. |
| `conductor-implement` | Ejecuta tareas del plan de implementación de una pista (track) siguiendo el flujo TDD (Test Driven Development). |
| `conductor-revert` | Deshacer consciente de git por unidad lógica de trabajo (pista, fase o tarea). |
| `debugger` | Especialista en depuración de errores, fallos de prueba y comportamiento inesperado. |
| `dependency-upgrade` | Gestiona actualizaciones mayores de dependencias con análisis de compatibilidad y pruebas exhaustivas. |
| `pentest-commands` | Ejecuta comandos de pentesting (nmap, metasploit, hydra, sqlmap) cuando el usuario lo solicita. |
| `performance-testing-review-multi-agent-review` | Revisión multi-agente para pruebas de rendimiento. |
| `playwright-skill` | Automatización completa de navegador con Playwright. Escribe scripts de prueba, rellena formularios, toma capturas. |
| `pypict-skill` | Generación de pruebas por pares (pairwise testing) usando pypict. |
| `screen-reader-testing` | Prueba aplicaciones web con lectores de pantalla (VoiceOver, NVDA, JAWS) para validar accesibilidad. |
| `startup-analyst` | Analista de negocios para startups (tamaño de mercado, modelos financieros). (Categorizada aquí en catálogo original). |
| `startup-metrics-framework` | Marco de métricas para startups (CAC, LTV, unit economics). (Categorizada aquí en catálogo original). |
| `systematic-debugging` | Enfoque sistemático para depurar cualquier bug o fallo de prueba antes de proponer arreglos. |
| `tdd-workflow` | Principios del flujo de trabajo TDD (Desarrollo Guiado por Pruebas): Ciclo ROJO-VERDE-REFACTOR. |
| `tdd-workflows-tdd-cycle` | Gestiona el ciclo completo de TDD. |
| `tdd-workflows-tdd-green` | Fase VERDE de TDD: Implementa el código mínimo necesario para que pasen las pruebas fallidas. |
| `tdd-workflows-tdd-red` | Fase ROJA de TDD: Genera pruebas fallidas para definir el comportamiento esperado. |
| `tdd-workflows-tdd-refactor` | Fase REFACTOR de TDD: Mejora el código sin cambiar su comportamiento externo. |
| `test-driven-development` | Úsalo al implementar cualquier característica o corrección, antes de escribir el código de implementación. |
| `test-fixing` | Ejecuta pruebas y arregla sistemáticamente todas las pruebas fallidas usando agrupación inteligente de errores. |
| `unit-testing-test-generate` | Genera pruebas unitarias completas y mantenibles con fuerte cobertura y foco en casos borde. |
| `web3-testing` | Prueba contratos inteligentes integralmente usando Hardhat y Foundry (unit, integration, forking). |
